# Документация проекта PILIGRIM

**PILIGRIM** — это мобильное приложение для ресторана, концептуально представляющее собой "духовно-гастрономическое путешествие". Разработано на Flutter с акцентом на высокую эстетику, плавные анимации и глубокий брендинг (обращение к пользователю "герой", поэтичные тексты, тотемы вместо классических иконок).

---

## 1. Архитектура и стек технологий

Проект построен с использованием чистой и масштабируемой **Feature-Driven Architecture** (функционально-модульная архитектура).

- **Фреймворк:** Flutter (Dart)
- **Управление состоянием (State Management):** `flutter_riverpod`
- **Видео/Медиа:** `video_player` (для TikTok-подобной ленты меню)
- **Графика:** `flutter_svg` (для отрисовки векторных логотипов и иконок-тотемов)

---

## 2. Структура директорий (`lib/`)

Код разделен на независимые модули (features) и общие ресурсы (core, data).

### 📁 `core/` (Ядро проекта)
Здесь лежат общие элементы, которые используются во всем приложении:
- `constants.dart` — константы путей к ассетам (SVG-тотемам) и общим настройкам.
- `theme.dart` — глобальная дизайн-система приложения, шрифты, цветовые схемы (M3), стили кнопок.
- `widgets/` — переиспользуемые UI-компоненты (например, анимированный фон `floating_totems_background.dart`).

### 📁 `data/` (Слой данных)
Общий слой для работы с внешними источниками:
- `models/` — базовые DTO-модели.
- `repositories/` — слой связи с бэкендом (API-клиенты).

### 📁 `features/` (Функциональные модули)
Каждая фича полностью изолирована и содержит свои `models`, `providers`, `widgets` и `[name]_screen.dart`.

1. **`navigation/`**
   - Управляет нижней панелью вкладок (`BottomNavigationBar`).
   - Содержит `MainScreen` и провайдер текущего индекса экрана `navigation_provider.dart`.

2. **`splash/`**
   - Экран запуска приложения (Онбординг). Обряд инициации для "героя".

3. **`home/`**
   - Главный экран. Содержит статус ресторана, концепцию и кнопку перехода к бронированию.
   - `booking_screen.dart` — форма заявки на бронирование стола.

4. **`menu/`**
   - Основной экран для просмотра блюд. Поддерживает два режима просмотра: List (список) и Video (TikTok-style полноэкранные карточки с видео). 

5. **`cart/`**
   - Корзина и логика оформления заказа ("Странствие").

6. **`afisha/`**
   - Раздел "Афиша" (Ивент-спейс «АУА»).
   - Вывод списка событий, карточки с ценами и возможностью записи.

7. **`profile/`**
   - "Летопись героя". Личный кабинет с историей странствий (бронирований) и настройкой пуш-уведомлений.

## 3. Дизайн-система (Брендбук)

Дизайн приложения строго подчиняется концепции:
- **Шрифт:** Только *Museo Sans* (300 для обычного текста, 700 для заголовков). Никаких шрифтов с засечками в UI.
- **Цветовая палитра:**
  - `Қара жер` (`#3D3A38`, `#2A2826`) — глубокие темные фоны земли.
  - `Ақ аспан` (`#F2EDE4`) — кремово-белый цвет текстов и светлых фонов.
  - `Мөлдір су` (`#7BA5B8`) — основной акцентный цвет (кнопки, иконки).
  - `Сары дала` (`#C4956A`) — теплый акцент для выделений.
  - `Піскен жеміс` (`#8B1A1A`) — цвет финального действия (например, отправка заявки).

## 4. Подключение Backend (API)

Проект полностью готов к подключению бэкенда. Благодаря `Riverpod` логика отображения данных не завязана на их источник.

### Пошаговый план интеграции:
1. **Добавление HTTP-клиента:** Добавить пакет `dio` или `http`.
2. **Создание репозиториев:** Внутри каждой фичи (например, `features/afisha/repositories/`) создать класс-репозиторий, который будет делать HTTP-запросы (GET, POST).
3. **Обновление моделей:** В классы типа `EventModel` добавить методы фабрики `fromJson` для парсинга JSON от бэкенда.
4. **Обновление Провайдеров:**
   - Заменить синхронные `Provider` (которые сейчас отдают mock-данные) на `FutureProvider` или `AsyncNotifierProvider`.
   ```dart
   final afishaEventsProvider = FutureProvider<List<EventModel>>((ref) async {
     final repository = ref.read(afishaRepositoryProvider);
     return repository.fetchEvents();
   });
   ```
5. **Обновление UI:**
   В виджетах использовать метод `.when()` для отображения состояния загрузки, ошибки или готовых данных. Больше ничего в UI менять не придется.

## 5. Запуск проекта
Проект использует стандартные инструменты Flutter.
Для запуска:
1. `flutter pub get` — установка зависимостей.
2. `flutter run` — запуск приложения на симуляторе/реальном устройстве.
